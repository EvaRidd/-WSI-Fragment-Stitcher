# 🔬 WSI Fragment Stitcher

Инструмент для автоматической реконструкции цифровых макропрепаратов из нескольких сканов формата `.mrxs` / `.tif` / `.tiff` / `.svs`.


## Как это работает


```
Шаг 1: Грубая регистрация на thumbnail (~2000px)
        → расход памяти ≈ 10 МБ, скорость < 10 сек

Шаг 2: Уточнение гомографии на патчах зоны перекрытия
        → читаем 6 патчей по 2048×2048 px через OpenSlide
        → каждый патч ≈ 12 МБ, в RAM одновременно один

Шаг 3: Запись результата тайлами (1024×1024 px)
        → в RAM одновременно одна полоса холста
        → весь холст никогда не создаётся

Итого: пиковый расход ≈ 200-400 МБ при любом размере слайдов
```

```
TASK1/
├── data/
│   ├── prostate_2/
│   │   ├── raw_images/
│   │   │   ├── fragment1.tif       # или .mrxs

│   └── prostate_4/
│       └── raw_images/
│           └── ...

├── config.json                     # настройки

```

>  **Важно для `.mrxs`**: рядом с каждым `.mrxs` файлом **обязательно** должна лежать папка с тем же именем (содержит тайлы данных). Без неё OpenSlide не откроет файл.
>
> ```
> raw_images/
>     fragment1.mrxs
>     fragment1/          ← эта папка обязательна!
>         Index
>         Data0000
>         ...
> ```

## Запуск

### Быстрый старт (только превью, без записи тяжёлого TIFF)

```bash
python stitch_wsi.py --data D:\TASK1\data\prostate_2 --no-tiff
```

### Полный запуск с записью результата

```bash
python stitch_wsi.py --data D:\TASK1\data\prostate_2 --config config.json
```

### Принудительно ручной режим (GUI с расстановкой точек)

```bash
python stitch_wsi.py --data D:\TASK1\data\prostate_2 --manual --no-tiff
```

### Принудительный выходной уровень пирамиды

```bash
python stitch_wsi.py --data D:\TASK1\data\prostate_2 --level 4
```

## Флаги командной строки

| Флаг | Описание |
|---|---|
| `--data` | Путь к папке с фрагментами (обязательный) |
| `--config` | Путь к JSON-конфигу (по умолчанию `config.json`) |
| `--output` | Папка для сохранения результата (по умолчанию `data/output`) |
| `--no-tiff` | Не записывать финальный TIFF, только превью и метрики |
| `--manual` | Сразу открыть ручной режим расстановки точек |
| `--level` | Принудительно использовать уровень пирамиды (0 = макс. разрешение) |

## Логика работы скрипта

```
Запуск
  │
  ├─ Найти все .mrxs/.tif/.tiff в папке raw_images/
  │
  ├─ Для каждой пары фрагментов:
  │   │
  │   ├─ [Автоматика] Грубая регистрация на thumbnail
  │   │       SIFT → BFMatcher → RANSAC → Гомография
  │   │
  │   ├─ [Автоматика] Уточнение по патчам зоны перекрытия
  │   │       Читаем 6 патчей через OpenSlide → SIFT → уточнённая H
  │   │
  │   └─ [Если автоматика провалилась] → открывается GUI
  │           Окно 1: кликаешь точки на фрагменте 1
  │           Окно 2: кликаешь те же точки на фрагменте 2
  │           Окно 3: проверка наложения → Enter/Esc
  │
  ├─ Вычислить размер холста
  │
  ├─ Записать результат тайлами (BigTIFF, JPEG-сжатие)
  │
  └─ Сохранить превью + отчёт + метрики
```

##  Ручной режим (GUI)

Открывается автоматически если автоматика не справилась, или принудительно через `--manual`.

**Управление:**
| Действие | Кнопка |
|---|---|
| Добавить точку | Левая кнопка мыши |
| Удалить последнюю точку | Правая кнопка мыши |
| Подтвердить / перейти дальше | `Enter` или `Пробел` |
| Отменить | `Esc` |

**Как правильно расставлять точки:**
1. Выбирай **характерные структуры**: края ткани, крупные железы, сосуды, границы фрагмента
2. Точки должны быть **видны на обоих фрагментах**
3. Минимум **4 точки**, лучше 6–8
4. Чем дальше точки друг от друга — тем точнее регистрация
5. Порядок точек на фрагменте 2 должен совпадать с порядком на фрагменте 1

После расстановки откроется окно проверки наложения (50/50 blend):
- Если ткань совпала → `Enter`
- Если плохо → `Esc` и запусти заново

## Выходные файлы

После запуска в папке `output/` появятся:

```
output/
├── registration_report.png     # визуальный отчёт: слайды + наложение
├── metrics.json                # метрики качества регистрации
├── prostate_2_preview.jpg      # быстрый просмотр результата
└── prostate_2_stitched.tiff    # финальный файл (BigTIFF, тайловый)
```

### Метрики качества

| Метрика | Описание |
|---|---|
| `rmse_um` | Среднеквадратичная ошибка регистрации в микрометрах |
| `confidence` | Доля инлайеров RANSAC (0–1) |
| `ssim` | Структурное сходство в зоне перекрытия (0–1) |
| `verdict` | ОТЛИЧНО / ПРИЕМЛЕМО / УДОВЛЕТВОРИТЕЛЬНО / НЕУДОВЛЕТВОРИТЕЛЬНО |

### Вердикты

| Вердикт | RMSE | SSIM |
|---|---|---|
| ОТЛИЧНО | < 5 мкм | > 0.7 |
| ПРИЕМЛЕМО | < 15 мкм | > 0.5 |
| УДОВЛЕТВОРИТЕЛЬНО | < 50 мкм | > 0.3 |
| НЕУДОВЛЕТВОРИТЕЛЬНО | ≥ 50 мкм | — |

## ⚙️ config.json

```json
{
  "thumb_max_px":   2000,
  "target_mb":      200,
  "output_level":   null,
  "refine_patches": 6,
  "refine_patch_px": 2048,
  "write_full_tiff": true,
  "tile_size":      1024,
  "blend_band_px":  256
}
```

| Параметр | Умолчание | Описание |
|---|---|---|
| `thumb_max_px` | 2000 | Размер thumbnail для грубой регистрации (px) |
| `target_mb` | 200 | Лимит RAM на один загружаемый уровень (МБ) |
| `output_level` | null | Уровень пирамиды для выходного файла (null = авто) |
| `refine_patches` | 6 | Количество патчей для уточнения гомографии |
| `refine_patch_px` | 2048 | Размер патча уточнения (px) |
| `write_full_tiff` | true | Писать финальный TIFF или только превью |
| `tile_size` | 1024 | Размер тайла при записи BigTIFF |
| `blend_band_px` | 256 | Ширина зоны линейного блендинга на стыке (px) |
